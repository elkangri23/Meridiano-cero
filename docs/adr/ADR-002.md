# ADR-002 Monolito modular

Estado: aceptado como decisión de implementación del plan. Fecha: 2026-10-27.
Trazabilidad: SPEC-012; REQ-Q01; T1-02; ACC-040.

## Contexto

Separar dominio de infraestructura sin generar capas vacías.

## Decisión

Una base de código con límites de paquetes y API; worker en fase 4. Crear módulos por consumidor real.

## Alternativas

Microservicios/Kubernetes añaden operación innecesaria; un archivo monolítico impide revisar reglas.

## Consecuencias y revisión

API y worker reutilizan servicios de dominio, no controladores. Revisar cuando existan medidas de capacidad que lo exijan.

## Separación de integridad y motor puro

2026-10-29: SHA-256/canonicalización vive en la entrada explícita de servidor @meridiano/case-schema/server. La raíz de case-schema conserva tipos/validación sin importar esa entrada. API prepara la huella sobre su copia estable y la entrega a createInitialRun; el motor no calcula hashes ni importa Node.

Alternativas descartadas: permitir crypto en la regla engine-pure, implementar SHA-256 propio o crear otro paquete sin necesidad. Consecuencias: firma interna de creación con huella obligatoria; mismo algoritmo, contenido y estado persistido. Las reglas de imports impiden también reintroducir esa entrada de servidor en motor o raíz pura. No cambia engineVersion=4 porque no cambian reglas, cronología ni representación persistida.
